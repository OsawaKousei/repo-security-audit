# ドキュメント一覧

入口はルートの [AGENT.md](../AGENT.md) と本書とする。計画と、実装済みの確定仕様を分けて管理する。

## 計画と確定仕様

| 配置先 | 記載する内容 | 現在の状態 |
|---|---|---|
| [実装計画](plan/implementation-plan.md) | 未実装の機能要件・関連文書への案内 | Phase 1反映済み範囲と後続Phaseの要件 |
| [確定仕様](spec/README.md) | 実装・検証済みの実際の動作・契約・制約 | ローカル基本仕様・Phase 1検証記録を追加 |
| [未確定事項](decisions.md) | 計画を実装する前に決める値・方式 | IDごとに管理 |

実装計画の採用方針やサンプルを、実装済みの仕様として扱わない。実装・検証が完了した範囲を `docs/spec/` に記載し、計画にも反映済み範囲を記録する。

## 用途別の担当文書

以下の分野の要件・手順は、各担当文書に一本化する。実装計画には詳細を複製せず参照を置く。これらも実装済みを示す文書ではない。要求の変更は担当文書へ反映し、他の分野へ影響する場合は関係する文書も整合させる。

| 目的 | 文書 |
|---|---|
| 目的・範囲・採用技術を把握する | [プロジェクト概要](overview.md) |
| AWSとローカルの全体構成を理解する | [アーキテクチャ](architecture.md) |
| 現行のコード配置と実装先を確認する | [リポジトリ構成](dev/repository.md) |
| 依存関係・Compose・ローカル実行を扱う | [ローカル開発](dev/local-development.md) |
| 実装順序・日常開発・操作時の確認を知る | [開発ワークフロー](dev/workflow.md) |
| 認証・外部入力・秘密情報・費用を扱う | [セキュリティ要件](security.md) |
| Terraform・AWS配信・環境分離・監視を扱う | [インフラ・運用](infra/terraform.md) |
| テスト・受け入れ条件を確認する | [検証計画](testing.md) |

## 統合の経緯と優先順位

旧基本仕様書 v0.1.0と旧ローカル開発環境変更要件書 v1.0.0は、変更要件を優先して統合し、旧 `docs/spec/` の5文書とともに旧文書を削除した。現在は[旧要件の対応先](plan/implementation-plan.md#coverage)に従い、機能要件を実装計画、共通要件・手順を各担当文書で管理する。廃止文書を実装時の参照先にはしない。

ユーザーの明示的な変更指示を優先する。リポジトリ構成は現行の `frontend/app`・`api/app`・`workers/security-audit/app` と `docker-compose.yaml` を正とする。

`docs/plan/` の実装計画はGit管理対象とする。2026-11-01にPhase 1のローカル基本実装を追加した。起動は[ルートREADME](../README.md)、実際の契約と検証根拠は[確定仕様](spec/README.md)を参照する。実GitHub・npm監査・AI、Cognito、Terraform、AWS統合は後続Phaseで実装する。
